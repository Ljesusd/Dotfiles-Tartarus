# Checkpoint — TartarusShell: fusión Bar + Launcher

**Estado:** funcional.

## Estructura actual

```text
TartarusShell/
├── shell.qml
├── bar/
│   ├── Bar.qml
│   └── components/
│       ├── ActiveWindow.qml
│       ├── Audio.qml
│       ├── Clock.qml
│       ├── Network.qml
│       ├── SystemTray.qml
│       ├── Workspaces.qml
│       └── network/
│           └── NetworkPopup.qml
├── launcher/
│   ├── Launcher.qml
│   ├── assets/
│   └── components/
│       ├── AppItem.qml
│       └── SearchBar.qml
└── services/
    └── Applications.qml
```

## `shell.qml`

```qml
//@ pragma UseQApplication

import Quickshell
import "bar"
import "launcher"

ShellRoot {
    Bar {}

    Launcher {}
}
```

`TartarusShell/shell.qml` es ahora el único entry point de Quickshell.

`ShellRoot` representa el shell completo y carga dos módulos independientes:

```text
ShellRoot
├── Bar
└── Launcher
```

`UseQApplication` se mantiene porque el `SystemTray` necesita soporte para los menús de plataforma.

## Bar

La barra no necesitó cambios importantes durante la fusión.

```text
Bar.qml
└── PanelWindow
    ├── Workspaces
    ├── ActiveWindow
    ├── SystemTray
    ├── Network
    ├── Audio
    └── Clock
```

`Bar.qml` continúa siendo responsable de su propia `PanelWindow`.

Esto mantiene la barra encapsulada: `shell.qml` solo necesita saber que existe un componente llamado `Bar`.

## Launcher

El antiguo:

```text
Launcher/shell.qml
```

fue transformado en:

```text
TartarusShell/launcher/Launcher.qml
```

El cambio arquitectónico principal fue:

```qml
ShellRoot {
```

por:

```qml
Scope {
```

Antes, Launcher se comportaba como una aplicación Quickshell completa.

Ahora es un módulo de TartarusShell.

La estructura conceptual es:

```text
Launcher
├── GlobalShortcut
└── launcherWindow
    ├── Applications
    ├── búsqueda
    └── lista de aplicaciones
```

## `Scope`

`Launcher.qml` usa:

```qml
Scope {
    ...
}
```

en lugar de crear otro `ShellRoot`.

Esto permite agrupar:

```qml
GlobalShortcut {}
PanelWindow {}
```

dentro de un componente reutilizable.

En lenguaje natural:

```text
ShellRoot
    "Soy TartarusShell completo."

Scope de Launcher
    "Soy solamente una parte de TartarusShell."
```

## Ventana del launcher

El identificador pasó de:

```qml
id: launcher
```

a:

```qml
id: launcherWindow
```

para diferenciar claramente:

```text
Launcher
```

el módulo,

de:

```text
launcherWindow
```

la ventana gráfica.

Por ejemplo:

```qml
launcherWindow.visible = true
```

significa explícitamente:

> mostrar la ventana del launcher.

## Applications service

`Applications.qml` ahora está en:

```text
TartarusShell/services/Applications.qml
```

y `Launcher.qml` lo importa mediante:

```qml
import "../services"
```

La decisión de diseño es que `Applications` representa datos/lógica del shell, no una pieza visual específica del launcher.

Esto permitirá eventualmente que otros módulos consuman el mismo servicio.

Conceptualmente:

```text
             Applications
                  │
         ┌────────┴────────┐
         │                 │
     Launcher          otro módulo
```

aunque actualmente solo Launcher lo utiliza.

## GlobalShortcut

El shortcut permanece dentro de `Launcher.qml`:

```qml
GlobalShortcut {
    name: "launcher"
    description: "Toggle application launcher"

    onPressed: {
        launcherWindow.toggleLauncher()
    }
}
```

Esto mantiene juntas las cosas relacionadas con Launcher.

No llenamos el `shell.qml` principal con detalles internos.

La intención arquitectónica es mantener algo así:

```qml
ShellRoot {
    Bar {}
    Launcher {}
}
```

en vez de:

```qml
ShellRoot {
    // lógica de barra
    // shortcut launcher
    // lógica launcher
    // servicios
    // ventanas
    // etc...
}
```

## Siguiente paso

El punto pendiente más evidente está dentro del launcher.

Actualmente existen:

```text
launcher/components/
├── AppItem.qml
└── SearchBar.qml
```

pero `Launcher.qml` todavía implementa esas dos partes directamente con:

```qml
TextInput {}
```

y:

```qml
delegate: Rectangle {}
```

Así que el siguiente checkpoint debería ser modularizar Launcher para que realmente use:

```text
SearchBar.qml
AppItem.qml
```

sin cambiar su comportamiento actual.
