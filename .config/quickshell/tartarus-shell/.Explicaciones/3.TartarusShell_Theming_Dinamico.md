# Checkpoint — TartarusShell: sistema de temas dinámicos

**Estado:** funcional.

## Objetivo de este checkpoint

Construir una infraestructura de theming para TartarusShell basada en:

- `Style.qml` para design tokens no cromáticos.
- Paletas externas en `colors.toml`.
- Un helper Python que valida y transforma la paleta activa.
- `active-theme.json` como contrato runtime.
- `Color.qml` como singleton reactivo para QML.
- Cambio de tema en caliente sin reiniciar Quickshell.

## Arquitectura actual

```text
TartarusShell/
├── shell.qml
├── bar/
├── launcher/
├── services/
├── scripts/
│   └── theme.py
└── theme/
    ├── qmldir
    ├── Style.qml
    ├── Color.qml
    └── palettes/
        ├── catppuccin-mocha/
        │   └── colors.toml
        └── tokyo-night-storm/
            └── colors.toml
```

## Flujo de datos del tema

```text
colors.toml
    ↓
theme.py
    ↓
active-theme.json
    ↓
Color.qml
    ↓
TartarusShell UI
```

El objetivo de diseño es que los componentes QML no conozcan:

- Catppuccin.
- Tokyo Night.
- nombres internos de una paleta.
- rutas de archivos TOML.
- JSON runtime.
- lógica de validación.

Los componentes consumen exclusivamente roles semánticos:

```qml
Color.background
Color.surface
Color.selection
Color.foreground
Color.foregroundMuted
Color.accent
```

## `Style.qml`

`Style.qml` es un singleton QML dedicado a valores visuales no cromáticos.

Actualmente contiene escalas para:

```text
radius
spacing
padding
font sizes
icon sizes
control/item height
animation duration
```

Ejemplo conceptual:

```qml
readonly property int radiusSmall: 6
readonly property int radiusMedium: 10
readonly property int radiusLarge: 16

readonly property int spacingMedium: 12
readonly property int spacingLarge: 16

readonly property int paddingSmall: 8

readonly property int paddingLarge: 16

readonly property int fontSmall: 13
readonly property int fontNormal: 18
readonly property int fontLarge: 24

readonly property int iconSmall: 16
readonly property int iconMedium: 22
readonly property int iconLarge: 32

readonly property int controlHeight: 50
readonly property int itemHeight: 56

readonly property int animationFast: 100
readonly property int animationNormal: 180

```

### Responsabilidad de `Style`

```text
Style
├── tamaños
├── radios
├── spacing
├── padding
├── tipografía
└── animaciones
```

No contiene colores.

## Registro QML

`theme/qmldir` registra los singletons:

```text
module TartarusShell.Theme

singleton Style 1.0 Style.qml
singleton Color 1.0 Color.qml
```

Esto permite que los componentes importen `theme/` y usen:

```qml
Style.radiusMedium
Color.surface
```

## Formato de paletas

Cada paleta vive en:

```text
theme/palettes/<slug>/colors.toml
```

El formato distingue metadata, colores originales y roles semánticos.

Ejemplo conceptual:

```toml
name = "Catppuccin Mocha"
slug = "catppuccin-mocha"
mode = "dark"

[colors]
base = "#1e1e2e"
surface0 = "#313244"
mauve = "#cba6f7"
red = "#f38ba8"
green = "#a6e3a1"
yellow = "#f9e2af"

[roles]
background = "base"
surface = "surface0"
accent = "mauve"
error = "red"
warning = "yellow"
success = "green"
```

### Decisión de diseño

`[colors]` conserva el vocabulario propio de la paleta.

`[roles]` define cómo TartarusShell interpreta esa paleta.

Ejemplo:

```text
Catppuccin:
mauve
    ↓
roles.accent
    ↓
Color.accent
```

Esto permite que una paleta distinta use nombres completamente diferentes sin cambiar los componentes QML.

## `theme.py`

El helper Python vive en:

```text
scripts/theme.py
```

Su pipeline es:

```text
load_palette()
    ↓
validate_palette()
    ↓
resolve_roles()
    ↓
build_active_theme()
    ↓
write_active_theme()
```

### Responsabilidades

```text
1. Recibir el slug de una paleta.
2. Localizar colors.toml.
3. Parsearlo con tomllib.
4. Validar metadata.
5. Validar [colors].
6. Validar [roles].
7. Verificar que cada role referencia un color existente.
8. Resolver roles a colores hexadecimales.
9. Generar active-theme.json.
```

Uso actual:

```bash
python scripts/theme.py set catppuccin-mocha
```

o:

```bash
python scripts/theme.py set tokyo-night-storm
```

## Estado runtime

El helper escribe:

```text
~/.local/state/tartarus-shell/active-theme.json
```

Este archivo representa el tema actualmente seleccionado.

Se decidió no guardarlo dentro del repositorio porque es estado del usuario, no código fuente.

## Contrato Python ↔ QML

`active-theme.json` es el contrato estable entre el helper externo y Quickshell.

Esto permite migrar posteriormente:

```text
Python
    ↓
Rust
```

sin modificar `Color.qml`, siempre que la futura implementación Rust genere el mismo formato JSON.

## `Color.qml`

`Color.qml` es un singleton QML que:

```text
1. Lee active-theme.json.
2. Parsea JSON.
3. Expone metadata.
4. Expone roles semánticos.
5. Tiene valores fallback.
6. Vigila cambios del archivo.
7. Recarga el tema automáticamente.
```

Interfaz conceptual:

```qml
Color.name
Color.slug
Color.mode

Color.background
Color.backgroundAlt
Color.surface
Color.surfaceHover
Color.selection

Color.foreground
Color.foregroundMuted
Color.foregroundSubtle

Color.accent

Color.error
Color.warning
Color.success
Color.info
```

## Hot reload

`Color.qml` usa `FileView` con vigilancia de cambios.

Flujo:

```text
theme.py escribe active-theme.json
        ↓
FileView detecta fileChanged
        ↓
reload()
        ↓
text cambia
        ↓
loadTheme()
        ↓
themeData cambia
        ↓
Color.* se reevalúa
        ↓
UI cambia
```

Esto permite cambiar de paleta sin reiniciar Quickshell.
