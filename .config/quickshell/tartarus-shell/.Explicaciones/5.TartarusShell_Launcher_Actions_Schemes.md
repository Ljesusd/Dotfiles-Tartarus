# Checkpoint — TartarusShell: Launcher con Actions y Schemes

**Estado:** funcional.

Documentar la evolución del Launcher de TartarusShell hacia un modelo de navegación por acciones:


# Flujo general del Launcher

El launcher distingue tres modos:

```text
applications
actions
schemes
```

La selección depende del contenido del SearchBar:

```text
"firefox"
→ applications

">"
→ actions

">sch"
→ actions

">scheme"
→ schemes
```

Conceptualmente:

```qml
readonly property string mode: {
    const query = search.query
        .trim()
        .toLowerCase()

    if (query.startsWith(">scheme"))
        return "schemes"

    if (query.startsWith(">"))
        return "actions"

    return "applications"
}
```

## Decisión de diseño

No se usan pestañas fijas como:

```text
Applications | Themes
```

El SearchBar determina el contexto, lo que prepara futuras acciones como:

```text
>scheme
>wallpaper
>power
>settings
```

# LauncherActions.qml

Responsabilidad:

```text
definir las acciones disponibles
filtrar acciones según búsqueda
```

Actualmente contiene:

```text
Scheme
```

con estructura conceptual:

```qml
{
    name: "Scheme",
    command: "scheme",
    description: "Change the current colour scheme"
}
```

`name` es presentación y `command` es identidad lógica.

# Filtrado de Actions

`LauncherActions.qml` expone:

```qml
filtered(query)
```

Ejemplos:

```text
>
→ query = ""
→ muestra todas las acciones

>sch
→ query = "sch"
→ muestra Scheme
```

# ActionItem.qml

API:

```qml
required property var action
required property bool selected

signal activated()
signal hovered()
```

El componente recibe datos y emite eventos. No conoce el SearchBar ni cambia el modo por sí mismo.

Estados visuales:

```text
selected → Color.selection
hover    → Color.surfaceHover
normal   → transparent
```

Muestra:

```text
Scheme
Change the current colour scheme
```

# Flujo al escribir `>`

```text
SearchBar
query = ">"
    ↓
launcher.mode = actions
    ↓
actionList.visible = true
    ↓
LauncherActions.filtered("")
    ↓
ActionItem: Scheme
```

# Activación de Scheme

Mouse y teclado usan el mismo flujo:

```text
ActionItem.activated()
↓
Launcher.activateAction(action)
↓
search.query = ">" + action.command
↓
>scheme
```

Como `mode` depende del query:

```text
>scheme
↓
mode = schemes
```

No se asigna `mode` manualmente.

# Themes.qml

Responsabilidad:

```text
descubrir themes
saber cuál está activo
cambiar theme
```

API principal:

```text
themes.themes
themes.currentSlug
themes.setTheme(slug)
```


# ThemeItem.qml

API:

```qml
required property var theme
required property bool selected

signal activated()
signal hovered()
```

Presentación conceptual:

```text
┌──────────────────────────────────────┐
│ Catppuccin Mocha              Active │
│ dark                                 │
│ ▰  ▰  ▰  ▰  ▰                       │
└──────────────────────────────────────┘
```

La lista de schemes usa una sola columna con `ListView`.

Estados:

```text
normal → Color.surface
hover  → Color.surfaceHover
activo → Color.selection
```

El indicador `Active` usa `Color.accent`.

# Selección del theme activo

```text
modelData.slug === themes.currentSlug
```

Ejemplo:

```text
modelData.slug = catppuccin-mocha
themes.currentSlug = catppuccin-mocha
↓
selected = true
```

# Cambio de theme

Flujo:

```text
ThemeItem
↓
Launcher.qml
↓
Themes.qml
↓
theme.py set <slug>
↓
active-theme.json
↓
Color.qml hot reload
↓
Launcher + Bar cambian en vivo
```

El launcher permanece abierto al cambiar de theme para permitir comparar varias opciones.

# Hot reload

```text
active-theme.json
↓
Color.qml
↓
watchChanges
↓
reload
```

No es necesario reiniciar Quickshell al cambiar entre Catppuccin Mocha y Tokyo Night Storm.
