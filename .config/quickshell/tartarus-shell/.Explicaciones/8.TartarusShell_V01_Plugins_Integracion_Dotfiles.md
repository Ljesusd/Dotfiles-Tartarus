## 3. Plugin System V1

Cada plugin sigue:

```text
plugin/
├── manifest.json
├── qmldir
├── Plugin.qml
├── Service.qml
├── BarWidget.qml
└── Panel.qml
```

Capabilities actuales:

```text
service
bar-widget
panel
```

### PluginRegistry

Mantiene `plugins`, evita registros duplicados y emite:

```qml
signal pluginRegistered(var plugin)
```

solo cuando el plugin es realmente nuevo.

Esto es importante porque `Bar.qml` y `shell.qml` mantienen modelos incrementales y no deben recrear delegates al registrar nuevos plugins.

### PluginDiscovery

Recorre dinámicamente `plugins/`, lee `manifest.json`, valida `id`, capabilities y entry points, carga `Plugin.qml` y registra la instancia.

El shell no hardcodea Network/Audio/Bluetooth/Brightness.


## 4. Responsabilidades

### Plugin.qml

Se encarga de:
- una instancia del Service;
- `panelOpened`;
- `panelAnchor`;
- lifecycle;
- Components de BarWidget/Panel.

Contrato conceptual:

```qml
function openPanel(anchor) {
    panelAnchor = anchor
    panelOpened = true
}

function closePanel() {
    panelOpened = false
}
```

**Regla crítica:** no poner `panelAnchor = null` al cerrar. El PopupWindow puede seguir usando el anchor durante el cierre y eso produjo inestabilidad/crashes.

### Service.qml

Backend, estado y acciones. No UI.

### BarWidget.qml

Presentación compacta e interacción rápida. Emite:

```qml
signal interacted()
```

para que Bar cierre el Launcher sin que el plugin conozca `LauncherState`.

### Panel.qml

UI interactiva usando el mismo Service.


## 5. ListModels incrementales

Problema inicial:

```qml
pluginRegistry.pluginsWithCapability(...)
```

devuelve arrays JS nuevos y podía recrear delegates.

Se observó:

```text
Bluetooth Panel CREATED
Bluetooth Panel CREATED
Network Panel CREATED
Bluetooth Panel DESTROYED
```

Solución:

```text
PluginRegistry.pluginRegistered(plugin)
→ ListModel incremental
→ delegates existentes permanecen vivos
```


## 6. Anchors de paneles

Cada plugin de la barra se envuelve en un `pluginSlot` de altura completa:

```text
pluginSlot
→ altura Style.barHeight
→ Loader centrado
```

Al cargar el BarWidget:

```qml
item.panelAnchorItem = pluginSlot
```

El Panel usa ese slot como anchor.

Resultado: popups alineados desde el borde real inferior de la barra y separados por `Style.barPopupGap`.

**No volver a geometría aproximada basada en tamaños del widget.**

## 10. Audio v0.1

Validado:

```text
volumen            ✓
mute               ✓
scroll             ✓
panel              ✓
selector de output ✓
```

Backend: `Quickshell.Services.Pipewire`.

Outputs:

```qml
readonly property ScriptModel outputsModel: ScriptModel {
    values: Pipewire.nodes.values.filter(node =>
        node
        && node.audio
        && node.isSink
        && !node.isStream
    )
}
```

Interpretación:
- `node.audio`: nodo de audio;
- `node.isSink`: salida;
- `!node.isStream`: no es una aplicación.

Output actual:

```qml
Pipewire.defaultAudioSink
```

Cambio solicitado:

```qml
Pipewire.preferredDefaultAudioSink = output
```

No se escribe en `defaultAudioSink`, porque representa la fuente de verdad.

## 13. Bluetooth Panel OFF y Qt Layouts

El popup no se movía; se movía el contenido interno.

Estructura corregida:

```text
Panel
├── Header fijo arriba
└── Body
    ├── ON
    └── OFF centrado
```

Warning posterior:

```text
Detected anchors on an item that is managed by a layout
```

Regla:

Si el padre es `ColumnLayout`, `RowLayout` o `GridLayout`, los hijos directos deben usar propiedades `Layout.*`.

Incorrecto:

```qml
anchors.horizontalCenter: parent.horizontalCenter
```

Correcto:

```qml
Layout.alignment: Qt.AlignHCenter
```

### MSI DDC quirk

Ruta normal:

```bash

```

no funcionaba correctamente en un monitor de prueba.

Ruta funcional:

```bash

```

Service aprende por sesión:

```text
writeMode unknown
→ intentar normal
→ si funciona: normal
→ si falla: noverify + scs
→ writeMode scs
```

No existe `if model == MSI`.

### Watch OSD

Se usa:

```bash
ddcutil watch --x52-no-fifo --bus BUS
```

Versión probada:

```text
ddcutil 2.2.7
```

Para procesos cortos usar `Process.onExited`.

Para `watch`, que es persistente, usar `SplitParser`.

No confundir `StdioCollector.onStreamFinished` con terminación real del proceso.

## 19. Hyprland + Quickshell IPC

Hyprland usa Lua.

Autostart de TartarusShell:

```text
qs -c tartarus-shell
```

Conceptualmente:

```lua
hl.on("hyprland.start", function()
    hl.exec_cmd("qs -c tartarus-shell")
end)
```

TartarusShell expone IPC:

```text
launcher.toggle()
launcher.open()
launcher.close()
```

Comando funcional:

```bash
qs ipc -c tartarus-shell call launcher toggle
```

Bind final:

```text
SUPER + R
→ Hyprland
→ qs ipc -c tartarus-shell call launcher toggle
→ LauncherState.toggle()
```

Antes `SUPER+R` abría Rofi.

Diseño: Hyprland conoce una acción pública (`toggle launcher`), no los internals del QML.

## 23. Decisiones de diseño que no conviene olvidar

1. **Backend fuera de la UI.**
   `Service.qml` conoce PipeWire/BlueZ/DDC/NetworkManager; Panel y BarWidget presentan.

2. **No invalidar `panelAnchor` al cerrar.**
   Mantenerlo válido mientras el PopupWindow termina su lifecycle.

3. **No recalcular arrays para delegates persistentes.**
   Usar modelos incrementales cuando importe preservar instancias.

4. **No hardcodear hardware.**
   Detectar buses, dispositivos, interfaces y modelos en runtime.

5. **Quickshell IPC como frontera con Hyprland.**
   Hyprland llama acciones públicas; no conoce internals del Launcher.

6. **Dotfiles como source of truth.**
   Los archivos reales están en `~/dotfiles`; `~/.config` apunta a ellos.

7. **No mezclar Layout y anchors en hijos directos gestionados por Layout.**

8. **Cada función debe tener responsabilidad clara.**
   Ejemplo Bluetooth: `setEnabled()` no debe ser parte implícita de `startScan()`.
